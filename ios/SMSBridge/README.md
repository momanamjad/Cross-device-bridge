# SMSBridge iOS App (WebRTC & SMS Client)

A native iOS client application written in **Swift & SwiftUI** utilizing the **Combine** framework. It acts as the secondary phone endpoint connecting directly to the **Realme C3 (Android)** embedded server.

---

## Features
- **Cellular Inbound Forwarding**: Real-time incoming calls presentation with Accept/Decline options.
- **P2P Audio Call**: Crystal clear voice stream via WebRTC.
- **Remote Dialer**: Keyboard interface to place cellular calls directly from the iPhone through Realme's SIM card.
- **SMS Sync Logs**: Pull-to-refresh list of received SMS logs from the Realme device.
- **Call History**: Categorized history log with durations.
- **Settings Store**: Automatic server discovery registration and UserDefaults settings persistence.

---

## Setup & Run Instructions

Since Xcode compilation and iOS packaging require **macOS**, transfer the `ios/SMSBridge` directory to a Mac machine and follow these setup steps:

### Prerequisites
- macOS Sonoma (14.0+)
- Xcode 15.0+
- CocoaPods (`sudo gem install cocoapods`)

### 1. Install Dependencies
Open a Terminal in the `ios/SMSBridge` folder and install the native WebRTC and Socket.io packages:
```bash
pod install
```
*Note: This generates an `SMSBridge.xcworkspace` workspace file.*

### 2. Open Project in Xcode
Double-click `SMSBridge.xcworkspace` to load it in Xcode.

### 3. Connect to Realme Hub
1. Launch the Android app on your **Realme C3** to boot the embedded server.
2. Note the Realme C3's local Wi-Fi IP address (e.g. `192.168.1.100`).
3. Build and run the `SMSBridge` target in Xcode on either the iOS Simulator or a physical iPhone.
4. Navigate to the **Settings** tab.
5. Enter the **IP Address**, **Port** (default `9000`), and tap **Register & Connect**.
6. Once connected, a green `Connected ✅` status will appear. Tab listings will refresh, and socket messaging will stream live!

## Signalling and WebRTC Architecture

- **Realme C3 (Offerer)**: Because the Android phone owns the SIM card and starts/receives the raw network streams, **Realme C3 is always the WebRTC SDP Offerer**.
- **iPhone (Answerer)**: The iOS client registers, listens on Socket.io for `webrtc:offer`, and replies with a `webrtc:answer` generated by its local `RTCPeerConnection`.
- **ICE Candidate Exchange**: Shared local candidates are sent asynchronously via `webrtc:ice-candidate` to negotiate the best P2P audio route (local network, stun, turn).
